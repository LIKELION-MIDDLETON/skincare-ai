# 1일 사용량·가격 계산 방식 변경

> PR #9. 추천 결과에 표시되는 `일일용량`/`일일가격`을 `총용량÷7` 방식에서
> 카테고리별 권장 사용량 기준으로 바꾼 기록.
>
> 후속 수정(2026-08-20): PR #9 반영 후 발견된 5가지 문제를 고쳤다. 아래
> "후속 수정" 절 참고.

## 배경

`ml_engine.recommend()`는 추천 상품마다 `일일용량`(1일 사용량)과 `일일가격`을
같이 반환한다. 기존 방식은 상품의 총 용량과 정가를 그대로 7로 나눴다.

```python
일일가격 = round(정가 / 7)
일일용량 = round(총용량 / 7, 1)
```

문제는 상품마다 "한 병을 며칠에 걸쳐 쓰는지"가 전혀 다른데 전부 "7일 만에
다 쓴다"고 가정한다는 점이다. 그 결과:

| 상품 | 총용량 | 계산된 1일 사용량 |
|---|---|---|
| 토너 200ml | 200ml | 28.6ml |
| 로션 150ml | 150ml | 21.4ml |
| 세럼 15ml | 15ml | 2.1ml |

토너를 하루에 28.6ml씩 쓰는 사람은 없다. 실사용(피부과·업계 통용 기준
1회 1~2ml, 1일 2회)보다 10배 넘게 부풀려진 값이었다.

올리브영 크롤링 데이터(`oliveyoung_data/`)에는 '권장 사용량' 전용 필드가
없다는 것도 확인했다. `사용방법` 자유텍스트에 펌프·방울 수가 적힌 상품이
일부 있지만(카테고리별 10~45%, 나머지는 "적당량"이라 정량화 불가) 전체
상품을 커버하지 못해 그대로 쓸 수 있는 데이터 소스가 아니다.

## 변경한 것

### 1. `daily_usage.py` (신규) — 카테고리별 1일 권장 사용량 표

피부과·업계에서 통용되는 1회 사용량 × 1일 사용 횟수를 카테고리별로
고정해 두고, 정가를 그 비율만큼 나눈다(마진 없이 순수 비례 배분).

```python
일일가격 = round(정가 * 일일용량 / 총용량)
```

일부 예시:

| 카테고리 | 1회 사용량 | 1일 횟수 | 1일 사용량 |
|---|---|---|---|
| 스킨_토너 | 2.0ml | 2 | 4.0ml |
| 로션 | 1.0ml | 2 | 2.0ml |
| 크림 | 0.7g | 2 | 1.4g |
| 에센스_세럼_엠플 | 1.0ml | 2 | 2.0ml |

권장량 표에 없는 카테고리(`스킨케어세트` 등)이거나 상품의 용량 단위가
표와 안 맞으면(예: 크롤링 원문이 g여야 할 곳에 ml로 기록된 경우) 기존
`총용량÷7` 방식으로 폴백한다. **(이 폴백은 후속 수정에서 제거됨 — 아래 참고)**

### 2. 매/개 단위는 반내림~반올림 범위로 표시

시트팩·패드처럼 낱개로 쓰는 상품은 "1.4매"처럼 소수로 쪼갤 수 없다.
정수가 아니면 `floor~ceil` 범위로 보여준다(예: `10매÷7일` → `1~2매`).

### 3. 선스틱·선스프레이_선패치는 1일 단위 분할 자체를 하지 않음

문질러 바르는 스틱, 분사/부착형 제품은 "1일 몇 g/ml"로 쪼개는 게
실사용과 맞지 않는다. 이 두 카테고리는 `일일용량`/`일일가격` 대신
`전체용량`/`정가`를 그대로 반환한다(`ml_engine.NO_DAILY_SPLIT`).

### 4. `updater/build_capacity.py` — 매(장) 단위 파싱 우선순위 수정

시트팩·코팩·패치·패드·티슈_패드는 크롤링 원문이 `"30ml*10"`(장당 내용물
30ml × 10장)처럼 장당 용량을 먼저 적는 경우가 많다. 기존 파서는 이걸
"총 300ml"로 잘못 읽었다. 이 카테고리들은 "매/장" 표기를 최우선으로 찾고,
없으면 `<용량><단위> x <개수>` 꼴에서 뒤의 개수를 매수로 해석하도록 고쳤다.

### 5. 적합도 표시에서 (실측)/(예측) 라벨 제거

`render()` 출력에서 적합도 값 옆에 붙던 `(실측)`/`(예측)` 출처 표기를
뺐다. 내부 데이터(`적합도출처` 필드)는 그대로 유지된다.

## 후속 수정 (2026-08-20)

PR #9를 실제로 붙여 쓰면서 나온 5가지 문제를 고쳤다.

### A. 마스크팩/코팩/필링/패치/페이셜백을 정규 패키지 슬롯에서 제외

이 5개 카테고리는 원래부터 "매일 쓰는" 제품이 아니라 상황에 따라 쓰는
제품인데, `daily_usage.DAILY`에 "주 2회 사용 가정"(`2/7`) 같은 고정 빈도로
박아 넣고 매일 루틴 패키지에 끼워 팔고 있었다. 사용 시점·빈도에 대한 설명
텍스트도 전혀 없이 상품 추천만 나가는 상태였다.

이번엔 `package_rules.SLOTS`에서 이 5개 카테고리를 완전히 제거해 정규
패키지 추천 대상에서 뺐다(슬롯 7 "마스크/팩"은 통째로 삭제, 슬롯 8에서
코팩·필링_스크럼 제거). "상황에 따라 알아서 챙겨 쓰라"는 SOS(상황별 케어)
기능으로 다시 노출하는 건 별도 작업으로 남겨뒀다 — 이번 PR은 정규 패키지
계산에서 빼는 것까지만 한다. `daily_usage.DAILY`에서도 해당 5개 항목을
지웠다(더 이상 어떤 슬롯에서도 조회되지 않음).

### B. 카테고리 권장량이 없을 때의 `총용량÷7` 폴백 제거

`daily_usage.daily_amount()`가 카테고리를 못 찾거나(`스킨케어세트` 등),
상품 용량 데이터가 없거나 단위가 안 맞을 때 조용히 `총용량÷7`로 계산하고
있었다. PR #9 본문에서 문제 삼았던 바로 그 계산 방식이 예외 경로로 되살아나
있던 것 — 카테고리별 권장량이 없는 상품은 그대로 방치되어 있었다.

이제 이 경우엔 `NO_DAILY_SPLIT`(선스틱 등)과 동일하게 처리한다: 근거 없는
값을 만들지 않고 `전체용량`/`정가` 그대로 보여주고, `일일가격`/`일일용량`은
`null`로 둔다.

### C. `총액_일일` 합산 시 `일일가격`이 없는 상품도 몰래 `정가/7`로 더하던 버그 수정

선스틱처럼 상품 카드에는 `일일가격: null, 정가: 8900`으로 정직하게
보여주면서도, 총액(`총액_일일`) 계산 루프에서는:

```python
total += 일일가격 if 일일가격 is not None else round(best["_price"]/7)
```

로 **화면에 안 보이는 `정가/7`을 몰래 더하고 있었다**. 개별 카드 표시와
합계 로직이 서로 다른 가정을 쓰고 있어 총액이 논리적으로 맞지 않았다.
이제 `일일가격`이 `None`인 상품은 합계에 아예 포함하지 않는다(B의 폴백
제거와 자연스럽게 맞물려 해결됨). 선스틱 등은 슬롯에는 계속 남겨두되(추천은
계속 나감) 하루 총액에는 반영하지 않는 걸로 정리했다.

### D. 기획상품(1+1, 증정 등) 후보에서 제외

올리브영 크롤링 용량 필드는 "본품 100ml / 증정 30ml", "1+1", "본품+리필"처럼
여러 구성품이 합쳐진 표기를 그대로 담고 있는 경우가 많다. 이런 상품은 총
용량·가격이 실제 "쓰는 한 개"를 가리키지 않기 때문에 1일 사용량·가격
계산이 왜곡된다. 우리는 올리브영 대리구매 사이트가 아니라 성분 기준
추천이 목적이므로, 어느 구성품을 기준으로 나눌지 임의로 정하는 대신
상품명에 `기획`/`N+N`/`증정`이 들어간 상품을 후보에서 통째로 제외했다
(`ml_engine.BUNDLE` 정규식, 전체 카탈로그의 약 32%).

### E. 응답 필드명 `정가` → `판매가`

크롤링 원본 필드명이 `sale_price`(판매가)인데, API 응답에서는 이 값을
그대로 `정가`(할인 전 정상가라는 뜻)라는 이름으로 내보내고 있었다.
할인이 반영된 실제 판매가를 정상가로 표기하는 건 명백히 틀린 이름이라
`판매가`로 고쳤다. 영향받는 곳: `ml_engine.recommend()`가 반환하는
`구성[].판매가` 필드, `render()` 출력.

### 확인한 것

- `python3 ml_engine.py` 데모 재실행 — 마스크팩/코팩/필링/패치/페이셜백이
  더 이상 슬롯에 나오지 않고, `기획`/`1+1`/`증정` 상품도 안 나옴.
- 선스틱류가 후보로 뽑힌 케이스에서 `총액_일일`이 개별 카드 합계와 정확히
  일치하는지 확인(더 이상 숨은 `정가/7`이 안 더해짐).
- FastAPI `TestClient`로 `/recommend` 실제 호출 — 200 응답, 응답 JSON에
  `정가` 키가 전혀 없고 `판매가`로만 나옴을 확인.
